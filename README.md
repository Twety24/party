# فريق أغابي — المرحلة 1

اللي شغال في المرحلة دي: تسجيل حساب، دخول، خروج، استعادة كلمة السر، الصفحة الرئيسية للعضو، المقترحات، والرسائل (قراءة فقط). قاعدة البيانات الكاملة (الحضور والتقارير كمان) جاهزة من دلوقتي.

## الخطوات (حساب واحد بس دلوقتي: Supabase)

1. ادخل على supabase.com وسجّل (ببريدك أو GitHub). اضغط **New project**، اكتب اسم زي `agaby`، اختار كلمة سر لقاعدة البيانات واحفظها، واختار أقرب منطقة (مثلاً Frankfurt).
2. استنى دقيقتين لحد ما المشروع يجهز.
3. من القايمة الشمال: **SQL Editor** ← New query ← الصق محتوى الملف `supabase/migrations/001_schema.sql` كله ← **Run**. المفروض تظهر رسالة نجاح.
4. من **Authentication ← Providers ← Email**: اقفل خيار **Confirm email** (عشان الأعضاء يدخلوا على طول. هنرجع نقفله لما نربط Resend).
5. من **Project Settings ← API**: انسخ **Project URL** و **anon public key**.
6. في فولدر المشروع انسخ `.env.example` باسم `.env.local` والصق القيمتين.
7. شغّل:
   ```
   npm install
   npm run dev
   ```
   وافتح http://localhost:3000
8. سجّل حسابك من صفحة "حساب جديد"، وبعدين خلّي نفسك أدمن: من SQL Editor شغّل
   ```sql
   update public.profiles set role = 'admin' where email = 'بريدك@example.com';
   ```

بعد كده هنحتاج Vercel (للنشر) وResend (للإيميل) في المرحلتين 3 و4، وهشرحهم وقتها.

## المرحلة 2: جلسات الحضور وماسح الـ QR

مفيش حسابات جديدة. بس زوّد في `.env.local`:
- `SUPABASE_SERVICE_ROLE_KEY`: من **Project Settings ← API ← service_role** (سرّي. ما تبعتوش لحد وما تنزّلوش على GitHub).
- `ALLOW_TEST_SESSIONS=true`: عشان تجرّب من غير ما تستنى السبت. **امسحه قبل الاستخدام الحقيقي.**

التجربة: سجّل دخول بحساب الأدمن ← "جلسة الحضور (أدمن)" ← "جلسة تجريبية". افتح الموقع على موبايل بحساب عضو تاني (أو متصفح تاني)، واضغط "تسجيل الحضور" وامسح الكود من شاشة الأدمن.
ملاحظة: الكاميرا بتشتغل على localhost أو HTTPS بس. للتجربة على الموبايل انشر على Vercel أو استخدم نفس الجهاز.

ملاحظات أمان: الكود يتجدد كل 30 ثانية وبيتوقّع على السيرفر بمفتاح سري، والوقت بيتحسب بتوقيت السيرفر (القاهرة)، والعضو مسموحله تسجيل واحد في الاجتماع بقيد في قاعدة البيانات.

## المرحلة 3 و4: القفل التلقائي، التقارير، الإيميل، لوحة الأدمن

**1) قاعدة البيانات:** شغّل `supabase/migrations/002_admin_features.sql` في SQL Editor (مرة واحدة).

**2) الإيميل (Resend):** سجّل في resend.com، ومن **API Keys** اعمل مفتاح. ملحوظة: من غير دومين متوثّق، Resend بيبعت بس لبريد حسابك أنت فيه. فاستخدم نفس بريد حساب Resend كـ "بريد الأدمن" في البداية.

**3) في Vercel ← Settings ← Environment Variables** ضيف:
- `RESEND_API_KEY` = مفتاح Resend
- `CRON_SECRET` = كلمة سر طويلة عشوائية (ولّدها بـ `node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"`)
ثم **Redeploy** (Deployments ← ⋯ ← Redeploy).

**4) الجدولة:** افتح `003_cron.sql`، بدّل `YOUR_APP_URL` بلينك موقعك و`YOUR_CRON_SECRET` بنفس كلمة السر، وشغّله في SQL Editor. ده بيخلّي Supabase يستدعي الموقع كل دقيقة؛ فبيقفل الجلسة عند 11 مساءً بتوقيت القاهرة وبيحسب الغايبين ويطلع الملفين ويبعت الإيميل ويعيد المحاولة 3 مرات، وبعدها يبعتلك رسالة جوه التطبيق لو فشل.

**5)** من لوحة الأدمن ← **الإعدادات** اكتب بريد الأدمن. ومن **الأعضاء** تقدر ترقّي أي عضو لأدمن.

**تجربة كاملة:** جلسة تجريبية ← سجّل حضور بحساب تاني ← "إنهاء الجلسة الآن" ← صفحة التقارير ← تحقق من الإيميل. بعدها امسح `ALLOW_TEST_SESSIONS`.
